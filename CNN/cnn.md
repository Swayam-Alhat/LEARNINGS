working of CNN -

- Input image is converted into numerical format
- convolution is applied. for RGB Image, filter is replicated across each channel and sumed up to get single feature map
- CNN can have multiple filters. So, if there are 3 filters, then we get 3 features maps.
- After convolution, pooling is applied to decrease size of feature
- Pooling is applied to each feature map generated by each distinct filter
- This convolution and pooling can be repeated
- At the end, flatteing layer flattens feature map into 1d vector. If we have multiple features from multiple filters, then all feature maps are flatten together into single 1d vector
- This 1d vector is passed to fully connected network or ann or classifier for classification

Understanding how to know if size of filter is appropriate for input data size

formula : $\frac{(N - F)}{stride + 1}$

$N$ means size of input data  
$F$ means size of filter

Example,  
input image is $7 \times 7$ i.e $N = 7$  
filter is $3 \times 3$ i.e $F = 3$  
$stride = 1$  
so,  
$$\frac{(7 - 3)}{1 + 1} = 5$$

so, we will get 5 complete distinct places

if we get decimal number (non-integer), then it does not fit the input image  
Example,  
$stride = 3$  
$$\frac{(7 - 3)}{3 + 1} = 2.33$$

**So, this doesn't work**

Now, we can also use zero padding to preserves spatial size

To know, how much padding is needed, we have formula

$$\frac{F - 1}{2}$$

where $F$ is filter size

so, if

- F = 3 => zero pad with 1
- F = 5 => zero pad with 2
- F = 7 => zero pad with 3

**This preserves spatial size**

> [!Note]  
> 32x32 input is convolved repeatedly with 5x5 filter shrinks volumes spatially  
> i.e 32 -> 28 -> 24.  
> i.e size shrinks over time  
> **Shrinking too fast is not good**  
> because, in CNN, we would have 10 or 100 convolutional layers. So, we will get very small spatial size or representation (of original image) at the end  
> meaning, input size or representation of original image shrinks as they go deep  
> So, we want to perform deep convolution but without shrinking very fast
> **Thats why padding is useful**

### Case study: AlexNet

It used:

- ReLU
- Normalization layer (not used anymore now)
- heavy data augmentation (changing size, color, of input image)
- dropout 0.5 in fully connected layers
- batch size 128
- SGD Momentum 0.9
- Learning rate 1e-2 reduced by 10 manually when val accuracy plateaus
- L2 weight decay
- for single CNN, error rate at test time was 18.2%. When used 7 CNN ensemble, error rate was 15.4%

### ZFNet

Same as AlexNet but:

- AlexNet had 11x11 filter size & stride=4. ZFNet used 7x7 filter size and stride=2

- AlexNet used 384,384 and 256 filters in further convolutional layers. ZFNet changed it to 512, 1024 and 512 (increased number of filters)

ZFNet had 14.8% error rate

> [!Note]  
> Zeiler further made some changes in ZFNet and it produced 11% error rate

### VGGNet

It was 16 layer network. This had same size of filters and stride across network. It was much better. It's error rate was almost 7%

### GoogLeNet

They introduced Inception module. It has 12x less params than AlexNet. 2x more compute

### ResNet

By microsoft. It tells us that more layers improves performance.  
But,  
Increasing number of layers **naively** will result in poor performance.

So, we have to scale layers, but in ResNet way

**ResNet had skip connections**

ResNet:

- batch norm layer after every CONV layer
- Xavier initialization
- SGD/Momentum 0.9
- learning rate 0.1 and divided by 10 when validation error plateaus
- mini-batch size 256
- weight decay 1e-5
- No dropout (because if batch norm is present, network don't need dropout)
